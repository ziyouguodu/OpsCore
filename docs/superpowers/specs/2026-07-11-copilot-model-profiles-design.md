# AI Copilot 多模型配置设计

## 目标

将当前单条全局 AI Copilot 配置升级为可管理多个模型配置的工作区。管理员能够清楚查看已保存的厂商和模型，按厂商填写对应字段，测试连接，并显式选择唯一的当前启用配置。Copilot 问答始终使用当前启用配置。

## 范围

本次实现包括：

- 多模型配置的关系表存储与现有单配置迁移。
- 模型配置列表、创建、编辑、删除、连接测试和启用切换。
- Local 与 Hosted 厂商的条件字段展示。
- API Key 独立加密托管、脱敏响应和审计。
- 当前问答代理改为读取唯一启用配置。
- 前端方案 A 的列表优先工作区。

本次不包括：

- 按场景自动路由不同模型。
- 多模型并行推理、故障自动切换或负载均衡。
- API Key 明文回显。
- 普通角色管理或测试系统模型配置。

## 数据模型

新增 `copilot_model_configs` 表：

- `id`: 主键。
- `name`: 管理员可读的配置名称，非空且唯一。
- `provider`: `local`、`openai`、`anthropic`、`google` 或 `compatible`。
- `endpoint`: Hosted 模型服务地址；Local 配置可为空。
- `model`: Hosted 模型名称；Local 配置可为空。
- `local_endpoint`: Local 模型地址；Hosted 配置可为空。
- `local_model`: Local 模型名称；Hosted 配置可为空。
- `api_key_encrypted`: Hosted API Key 的 AES-GCM 密文；Local 配置为空。
- `temperature`: 数值，范围 `0` 到 `2`，默认 `0.2`。
- `max_tokens`: 整数，范围 `1` 到 `4096`，默认 `2048`。
- 四个上下文授权布尔字段。
- `is_active`: 是否为当前启用配置。
- `created_at`、`updated_at`。

数据库使用唯一部分索引保证最多只有一条 `is_active=true` 的记录。名称使用大小写不敏感唯一索引，避免出现仅大小写不同的重复配置。

## 迁移策略

迁移创建新表后，读取现有 `system_settings.copilot_config`：

- 如果存在配置，将其转换为名为“默认模型配置”的第一条记录。
- 保留原有加密 API Key，不进行明文解密和重新加密。
- 迁移后的配置设为当前启用。
- 如果没有现有配置，不自动创建可误认为已可用的 Hosted 配置；前端展示空状态并引导新增。
- 旧 `system_settings` 配置保留为兼容快照，但不再作为读取主源。

迁移必须幂等，并通过 `schema_migrations` 版本记录执行。

## API

新增或调整以下超级管理员接口：

- `GET /api/copilot/configs`: 返回全部配置的脱敏列表。
- `POST /api/copilot/configs`: 创建配置。首条配置自动设为当前启用。
- `PUT /api/copilot/configs/{id}`: 编辑指定配置。
- `DELETE /api/copilot/configs/{id}`: 删除非当前启用配置。
- `POST /api/copilot/configs/{id}/activate`: 原子切换当前启用配置。
- `POST /api/copilot/configs/{id}/test-connection`: 使用已托管密钥测试已保存配置。
- `POST /api/copilot/test-connection`: 保留用于新增或尚未保存表单的连接测试。

现有 `GET/PUT /api/copilot/config` 在过渡期保留兼容，但内部映射到当前启用配置。前端改用新接口后再评估移除时机。

所有响应只返回 `hasApiKey`，绝不返回密钥密文或明文。Hosted 配置修改厂商或 Endpoint 且未提交新 Key 时清理旧 Key；只修改名称、模型或生成参数时继续保留原 Key。Local 配置不接受或保留 API Key。

## 启用与删除规则

- 系统最多只有一个当前启用配置。
- 创建第一条配置时自动启用。
- 后续新建或编辑不会隐式切换当前模型。
- “设为当前”在数据库事务中先锁定相关记录，再完成原配置停用和目标配置启用。
- 当前启用配置不能直接删除。
- 非当前启用配置可以删除；只要系统已有配置，当前启用项保护规则保证至少保留一条配置。
- 启用前要求配置字段合法；Hosted 配置必须已有托管 Key，Local 配置无需 Key。
- 连接测试失败不自动停用当前配置，也不阻止保存草稿配置。

## 前端交互

页面采用已确认的“列表优先工作区”：

1. 顶部保留厂商选择卡片，作为新增配置时的快捷入口和厂商切换控件。
2. “已保存模型”表格展示配置名称、厂商、模型、Endpoint 摘要、密钥状态、启用状态和操作。
3. 当前启用行使用明确状态标识，不依赖整行高饱和背景。
4. 点击“新增配置”或“编辑”后，在列表下方展开编辑区；默认页面不展示空编辑表单。
5. 编辑区 Local 只显示配置名称、本地模型地址、本地模型、Temperature、最大输出和上下文授权。
6. Hosted 厂商只显示配置名称、API Endpoint、模型名称、API Key、Temperature、最大输出和上下文授权。
7. API Key 保存成功后清空输入框，只展示“已托管”。
8. 删除使用统一应用内确认弹窗；当前启用项的删除按钮禁用并提供原因提示。
9. 保存、测试、启用和删除完成后显示 Toast，并重新加载列表。
10. 参数中文标签使用“回答随机性（Temperature）”和“最大输出长度（Max Tokens）”，默认值分别为 `0.2` 和 `2048`。

## 错误处理与安全

- 继续沿用现有 Hosted Endpoint SSRF、重定向和 DNS 解析保护。
- 连接测试错误继续执行 API Key 清洗，不回显底层网络或 provider 敏感错误。
- 配置增删改、连接测试和启用切换记录服务端审计事件，审计详情不包含密钥。
- 仅 `super_admin` 可以调用配置管理和连接测试接口。
- Copilot 问答读取当前用户的数据库角色和当前启用配置，不信任客户端提供的配置 ID。
- 全新系统没有任何配置、迁移配置缺少密钥或当前模型连接不可用时，Copilot 问答返回明确、可操作但不泄密的错误。

## 测试

后端测试覆盖：

- 旧配置迁移及加密密钥保留。
- 创建首条配置自动启用。
- 多配置列表脱敏。
- 当前启用唯一性和并发切换。
- 当前配置禁止删除。
- Local/Hosted 字段及密钥规则。
- Hosted 厂商或 Endpoint 变化时清理旧密钥。
- 使用已托管密钥进行连接测试。
- Copilot 问答使用当前启用配置。
- 普通角色被拒绝。

前端单元和 E2E 覆盖：

- 非 Local 厂商不显示本地模型字段。
- Local 厂商不显示 Hosted Endpoint、模型和 API Key 字段。
- 空列表、新增、编辑、取消、保存、测试、启用和删除流程。
- 当前启用状态和密钥托管状态正确刷新。
- 当前配置删除禁用。
- 桌面与 390px 移动端无页面级横向溢出。

## 完成标准

- 管理员能同时保存至少三种厂商的配置且互不覆盖。
- 页面可清楚识别每条配置的厂商、模型、密钥状态和当前启用状态。
- 厂商表单不存在无关字段。
- 切换当前配置后，后续 Copilot 问答使用新配置。
- API、数据库和 UI 测试通过；Docker Compose 镜像重新构建并保持前后端与数据库健康。
- `AGENTS.md`、`WORKLOG.md` 和必要的 `README.md` 与真实行为一致。
